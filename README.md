# MIREA Connect

MCP-коннектор к РТУ МИРЭА для Claude, Codex, Cursor, Hermes, OpenClaw и других MCP-клиентов. Даёт ассистенту доступ к Пульсу (личное расписание, баллы БРС, посещаемость, турникеты), к СДО (online-edu.mirea.ru: курсы, дедлайны, оценки) и к публичному расписанию групп, преподавателей и аудиторий.

## Установка одной командой

**Windows** (PowerShell):
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/atomic-pancake-49/mirea-connect/main/install.ps1 | iex"
```

**macOS / Linux:**
```bash
curl -LsSf https://raw.githubusercontent.com/atomic-pancake-49/mirea-connect/main/install.sh | sh
```

Скрипт ставит [uv](https://docs.astral.sh/uv/) (если его нет) и сам коннектор, а потом спрашивает, куда его подключить. Python и git заранее ставить не нужно.

```text
Куда подключить MIREA Connect?

  1) Claude Desktop
  2) Codex
  3) Hermes Agent
  4) Другой агент или харнесс — показать промпт, он подключит коннектор сам

Номера через пробел (Enter — все найденные):
```

Последний пункт — для любого агента, которого нет в списке. Установщик покажет готовый промпт с точной командой запуска для вашего компьютера, сохранит его в `~/.config/pymirea/agent-prompt.txt` и скопирует в буфер обмена. Вставьте промпт агенту, и он подключит коннектор сам. Без вопросов: `mirea-connect install --all`.

| Клиент | Как подключается |
|---|---|
| Claude Desktop | `claude_desktop_config.json` |
| Claude Code | `claude mcp add --scope user` |
| Cursor | `~/.cursor/mcp.json` |
| Codex (CLI, IDE, приложение) | `codex mcp add`, без CLI — `~/.codex/config.toml` |
| Hermes Agent | `~/.hermes/config.yaml` → `mcp_servers`, потом `/reload-mcp` |
| OpenClaw | `openclaw mcp set` |

**Агент ещё ничего не ставил?** Можно поручить ему всё целиком, включая установку:

```text
Установи и подключи к себе MCP-сервер MIREA Connect по инструкции:
https://raw.githubusercontent.com/atomic-pancake-49/mirea-connect/main/llms-install.md
Перед изменением файлов спрашивай меня. Пароль и код МИРЭА у меня в чате не спрашивай.
```

`mirea-connect prompt` снова покажет промпт из установщика, `mirea-connect prompt --json` — только параметры сервера.

Перед правкой файлов делается копия `*.bak`. После установки перезапустите открытые клиенты. Если клиент поставили позже, выполните `mirea-connect install` ещё раз: повторный запуск ничего не дублирует.

**Вход в МИРЭА.** Напишите ассистенту «войди в МИРЭА». На этом компьютере откроется страница входа (`127.0.0.1`), где вводятся логин, пароль и код из почты. Есть и вариант из терминала: `mirea-connect login`.

Всё работает **на вашем устройстве**: пароль и сессия уходят только на сервера МИРЭА. Сессия хранится зашифрованной в `~/.config/pymirea/` (общая с CLI `pymirea`). Когда МИРЭА её сбросит, ассистент сам предложит войти заново.

```bash
mirea-connect status      # есть ли вход
mirea-connect logout      # удалить сессию с компьютера
mirea-connect uninstall   # отключить от клиентов
mirea-connect prompt      # промпт для любого другого агента
uv tool upgrade mirea-connect   # обновить
```

Локальный режим работает во всех клиентах из таблицы и в любом другом, который умеет запускать stdio MCP-серверы. Команду для ручной настройки покажет `mirea-connect install`, если не найдёт ни одного клиента. Для веб-версии claude.ai и телефона нужен удалённый сервер, см. [«Свой сервер»](#свой-сервер).

## Инструменты

| Инструмент | Нужен вход | Что делает |
|---|:---:|---|
| `timetable` | — | Расписание группы, преподавателя или аудитории на N дней |
| `search_timetable` | — | Поиск группы, преподавателя или аудитории |
| `free_rooms` | — | Свободные аудитории в интервал: список по корпусу или проверка конкретных |
| `my_schedule` | ✓ | Своё расписание из Пульса |
| `my_grades` | ✓ | Баллы БРС по всем предметам |
| `my_attendance` | ✓ | Посещаемость по дисциплине |
| `my_turnstile_events` | ✓ | Проходы через турникеты за сегодня |
| `my_sdo` | ✓ | СДО (Moodle): курсы, дедлайны, оценки |
| `whoami` | — | Кто подключён и есть ли живая сессия |
| `login` | — | Открыть страницу входа МИРЭА на этом компьютере (только локальный режим) |
| `delete_my_data` | — | Удалить свою сессию (с компьютера или с сервера) |

Все инструменты, кроме `delete_my_data`, только читают данные. Отметки посещаемости здесь нет.

## Подключение к удалённому серверу

Нужен адрес сервера вида `https://<хост>/mcp`. На главной странице сервера есть подсказки по клиентам.

- **claude.ai / Claude Desktop:** Настройки → Коннекторы → «Добавить свой коннектор» → вставьте адрес.
- **Claude Code:**
  ```bash
  claude mcp add --transport http mirea https://<хост>/mcp
  ```
- **Cursor и другие:** добавьте HTTP MCP-сервер с этим адресом.

При подключении откроется страница входа МИРЭА. Когда сессия Пульса истечёт (МИРЭА периодически сбрасывает их), ассистент попросит переподключить коннектор. Это делается в настройках клиента, в чат ничего вводить не нужно.

## Свой сервер

Удалённый сервер нужен, чтобы коннектор работал в веб-версии claude.ai и на телефоне. Он подключается по ссылке через OAuth: при подключении открывается страница входа МИРЭА, а без аккаунта доступен гостевой режим с публичным расписанием. В этом режиме сессии студентов хранятся на сервере того, кто его поднял, поэтому поднимайте его для себя и тех, кто вам доверяет.

**Какое железо нужно.** Нагрузка почти целиком сетевая. На 50 одновременно активных пользователей хватит 1 vCPU и 1 ГБ RAM: старый ноутбук, Raspberry Pi 4 или самый дешёвый VPS. Ограничивает не сервер, а МИРЭА: все запросы идут с одного IP. Поэтому лучше домашний IP (датацентры pulse.mirea.ru блокирует), а при большом числе пользователей стоит разносить нагрузку по нескольким серверам.

### Docker

```bash
git clone https://github.com/atomic-pancake-49/mirea-connect
cd mirea-connect
cp .env.example .env      # впишите PUBLIC_URL
docker compose up -d --build
```

Сервер слушает `127.0.0.1:8000`, данные лежат в `./data`: база SQLite и ключ шифрования `data/key`. **Сохраните ключ**: без него сессии не расшифровать.

### Без Docker

```bash
uv tool install https://github.com/atomic-pancake-49/mirea-connect/archive/refs/heads/main.zip
PUBLIC_URL=https://mirea.example.com DATA_DIR=~/.local/share/mirea-connect mirea-connect serve
```

### Наружу без белого IP

Клиентам нужен HTTPS-адрес. Подойдёт любой из вариантов:

**Cloudflare Tunnel** (нужен домен в Cloudflare, бесплатно):
1. Cloudflare Zero Trust → Networks → Tunnels → Create tunnel → скопируйте токен в `CLOUDFLARE_TUNNEL_TOKEN` в `.env`.
2. В настройках туннеля добавьте Public hostname, например `mirea.example.com` → `http://mirea-connect:8000`.
3. В `.env` укажите `PUBLIC_URL=https://mirea.example.com` и запустите:
   ```bash
   docker compose --profile tunnel up -d --build
   ```

**Tailscale Funnel** (домен не нужен, адрес вида `https://<машина>.<tailnet>.ts.net`):
```bash
tailscale funnel --bg 8000
```
В `PUBLIC_URL` впишите адрес, который покажет команда.

Домашний IP даже лучше VPS: pulse.mirea.ru блокирует датацентры. На VPS понадобится `MIREA_PROXY`.

### Настройки (`.env`)

| Переменная | По умолчанию | |
|---|---|---|
| `PUBLIC_URL` | `http://localhost:8000` | Внешний адрес. Должен совпадать с тем, что вводят в клиенте |
| `SESSION_KEYS` | генерируется в `data/key` | Ключ шифрования сессий. Через запятую можно передать несколько для ротации: первый шифрует, остальные только расшифровывают |
| `ALLOW_GUEST` | `true` | Разрешить вход без аккаунта МИРЭА |
| `MIREA_PROXY` | — | HTTP/SOCKS-прокси для запросов к МИРЭА |
| `ALLOWED_HOSTS` | — | Дополнительные значения заголовка Host через запятую |
| `HOST` / `PORT` | `127.0.0.1` / `8000` | Где слушать (в Docker `0.0.0.0`) |
| `DATA_DIR` | `./data` | Каталог для базы и ключа |

## Безопасность

- **Пароль МИРЭА** проходит через сервер один раз при входе и не записывается ни в базу, ни в логи.
- **Сессия Пульса** хранится зашифрованной (Fernet + HKDF из pymirea) и привязана к пользователю. Токены коннектора и OAuth-коды хранятся только в виде хешей SHA-256.
- **Изоляция пользователей.** Каждый видит только свои данные. Владелец сервера технически может получить доступ к сессиям на своём сервере, поэтому есть self-host.
- **Удаление данных.** `delete_my_data` удаляет сессию и отзывает токены. Отключение коннектора в клиенте делает то же самое по истечении токенов.
- **Ограничение попыток входа:** 10 попыток за 10 минут с одного IP и 5 на одну попытку подключения.

## Разработка

```bash
pip install -e ".[dev]"
pytest -q
ruff check .
```

Тесты проходят весь путь удалённого режима: регистрация клиента → `/authorize` → страница входа (гость, логин + OTP) → обмен кода → вызовы инструментов по MCP. Для локального режима проверяются страница входа на `127.0.0.1` и установщик. Запросы к МИРЭА в тестах мокаются.

## Источники

- **[atomic-pancake-49/pymirea](https://github.com/atomic-pancake-49/pymirea)**, форк [daftrent/pymirea](https://github.com/daftrent/pymirea) (MIT). Вся работа с МИРЭА: вход через SSO с 2FA, клиенты Пульса, БРС, СКУД, расписание, шифрование сессий.
- **[PowerTronin/mirea-mcp](https://github.com/PowerTronin/mirea-mcp)** (GPL-3.0). Оттуда взяты принципы: пароль не идёт через чат, инструменты только читают. Код не копировался. Это MCP для СДО (online-edu.mirea.ru) с курсами и дедлайнами, и он хорошо дополняет этот коннектор.
- **[mirea.ninja](https://mirea.ninja)** ([0niel/university-app](https://github.com/0niel/university-app)) — публичное расписание и свободные аудитории через их Supabase (`supabase.mirea.ninja`, публичные RPC с publishable-ключом). Запасной источник — официальный iCal `schedule-of.mirea.ru`. Старый `app-api.mirea.ninja` не используется.

Проект неофициальный и с РТУ МИРЭА не связан. Пульс — закрытый API, поэтому после изменений на стороне университета что-то может сломаться.
