# MIREA Connect

MCP-коннектор к РТУ МИРЭА для Claude, Codex, Cursor, Hermes, OpenClaw и других MCP-клиентов. Даёт ассистенту доступ к Пульсу (личное расписание, баллы БРС, посещаемость, турникеты), к СДО (online-edu.mirea.ru: курсы, дедлайны, оценки) и к публичному расписанию групп, преподавателей и аудиторий.

**Версия 0.2.0 — локальный CLI + stdio MCP.** Каждый пользователь входит со своей учётной записью; чужие сессии не нужны. Неофициальный проект: работоспособность зависит от API и разметки университета. Этот релиз не разворачивает публичный сервер и не подтверждает готовность legacy self-host-режима для чужих учётных данных.

Если `uv` уже установлен, можно поставить конкретный релиз без запуска shell-установщика:

```bash
uv tool install --python 3.12 https://github.com/atomic-pancake-49/mirea-connect/archive/refs/tags/v0.2.0.zip
mirea-connect --version
mirea-connect install
mirea-connect login
```

Уже установленную копию обновляют командой `uv tool upgrade mirea-connect`. Пароль и одноразовый код вводятся только в локальной странице входа или скрытом терминальном приглашении, не в чате.

## Установка одной командой

**Windows** (PowerShell):
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/atomic-pancake-49/mirea-connect/main/install.ps1 | iex"
```

**macOS / Linux:**
```bash
curl -LsSf https://raw.githubusercontent.com/atomic-pancake-49/mirea-connect/main/install.sh | sh
```

Скрипт ставит [uv](https://docs.astral.sh/uv/) (если его нет) и сам коннектор, а потом спрашивает, куда его подключить. Python и git заранее ставить не нужно.

```text
Куда подключить MIREA Connect?

  1) Claude Desktop
  2) Codex
  3) Hermes Agent
  4) Другой агент или харнесс — показать промпт, он подключит коннектор сам

Номера через пробел (Enter — все найденные):
```

Последний пункт — для любого агента, которого нет в списке. Установщик покажет готовый промпт с точной командой запуска для вашего компьютера, сохранит его в `~/.config/pymirea/agent-prompt.txt` и скопирует в буфер обмена. Вставьте промпт агенту, и он подключит коннектор сам. Без вопросов: `mirea-connect install --all`.

| Клиент | Как подключается |
|---|---|
| Claude Desktop | `claude_desktop_config.json` |
| Claude Code | `claude mcp add --scope user` |
| Cursor | `~/.cursor/mcp.json` |
| Codex (CLI, IDE, приложение) | `codex mcp add`, без CLI — `~/.codex/config.toml` |
| Hermes Agent | `~/.hermes/config.yaml` → `mcp_servers`; CLI: `/reload-mcp`, Desktop: перезагрузка MCP в настройках подключения либо перезапуск клиента |
| OpenClaw | `openclaw mcp set` |

**Агент ещё ничего не ставил?** Можно поручить ему всё целиком, включая установку:

```text
Установи и подключи к себе MCP-сервер MIREA Connect по инструкции:
https://raw.githubusercontent.com/atomic-pancake-49/mirea-connect/main/llms-install.md
Перед изменением файлов спрашивай меня. Пароль и код МИРЭА у меня в чате не спрашивай.
```

`mirea-connect prompt` снова покажет промпт из установщика, `mirea-connect prompt --json` — только параметры сервера.

Перед правкой файлов делается копия `*.bak`. После установки перезапустите открытые клиенты. Если клиент поставили позже, выполните `mirea-connect install` ещё раз: повторный запуск ничего не дублирует.

**Вход в МИРЭА.** Напишите ассистенту «войди в МИРЭА». На этом компьютере откроется страница входа (`127.0.0.1`), где вводятся логин, пароль и код из почты. Есть и вариант из терминала: `mirea-connect login`.

Всё работает **на вашем устройстве**. После callback состояние немедленно сохраняется как отдельный зашифрованный кандидат, до открытия необязательной конечной страницы. Ошибка этой страницы или обрыв связи не заставляют вводить тот же код снова. `verify-login` проверяет существующий кандидат чтением Pulse и СДО без пароля и нового OTP. Только успешное чтение Pulse создаёт новую активную версию; состояние СДО сообщается отдельно.

Хранилище CLI и локального MCP: `$PYMIREA_HOME` или `~/.config/pymirea/`. Новые зашифрованные версии лежат в `retained/`, каждый раз под новым именем; прежний `session.json`, ключ и предыдущие версии не заменяются и не удаляются. Старый формат `pymirea` читается как резервный; сама сторонняя CLI `pymirea` новые версии `retained/` не читает. Новая авторизация не уничтожает старую. Ключ должен оставаться защищённым: без него сессии не расшифровать.

```bash
mirea-connect verify-login                 # последний кандидат, без нового входа
mirea-connect verify-login <candidate_id> --json
```

Код выхода проверки: 0 — Pulse и СДО проверены; 2 — кандидат сохранён, но одна из проверок не подтверждена; 1 — кандидата нет или он недоступен. По частичному результату не надо автоматически запускать login: сначала исследуются сохранённое состояние и диагностика. Диагностика записывается один раз на попытку, содержит только разрешённые метаданные переходов/классов cookie, без значений, query, паролей, кодов или сырых имён неизвестных cookie. `MIREA_CONNECT_DIAGNOSTICS_DIR` задаёт её каталог. Флаг диагностики больше не меняет лимит OTP.

```bash
mirea-connect status      # есть ли вход
mirea-connect logout      # объяснить запрет удаления (сессии сохраняются)
mirea-connect uninstall   # отключить от клиентов
mirea-connect prompt      # промпт для любого другого агента
uv tool upgrade mirea-connect   # обновить
```

Локальный режим работает во всех клиентах из таблицы и в любом другом, который умеет запускать stdio MCP-серверы. Команду для ручной настройки покажет `mirea-connect install`, если не найдёт ни одного клиента. Для веб-версии claude.ai и телефона нужен удалённый сервер, см. [«Свой сервер»](#свой-сервер).

## Как CLI

Коннектор — это ещё и обычная утилита терминала (один `mirea-connect login` включает и CLI, и MCP):

```bash
mirea-connect login                         # вход в МИРЭА (пароль + код из почты)
mirea-connect schedule -d 3                 # своё расписание
mirea-connect grades                        # баллы БРС
mirea-connect attendance "Физика"           # посещаемость по дисциплине
mirea-connect acs                           # турникеты за сегодня
mirea-connect sdo                           # СДО: курсы, дедлайны, оценки
mirea-connect search teacher Осипов         # поиск (group | teacher | classroom)
mirea-connect timetable group ЭФБО-01-24    # публичное расписание (вход не нужен)
mirea-connect free-rooms 10:40 12:10 --campus В-78     # свободные аудитории
mirea-connect free-rooms 10:40 12:10 А-9 ИВЦ-124       # свободны ли эти
```

У каждой команды есть `--json`.

## Экспорт материалов СДО

```bash
mirea-connect materials --all                 # все доступные курсы
mirea-connect materials --course "Большие данные" --json  # один курс по названию
```

Локальный MCP-инструмент `export_materials()` делает то же самое; `export_materials(course="Большие данные")` ограничивает выгрузку одним курсом. Принимается и однозначная часть названия без учёта регистра. Если совпадений несколько, возвращаются варианты; ID знать не нужно. Возвращаются статус, счётчики и пути к ZIP и JSON-манифесту. Архивы сохраняются в `~/mirea-connect-exports/`, каждый под новым именем; существующие файлы не перезаписываются. `MIREA_EXPORT_DIR` позволяет задать другой абсолютный каталог. Экспорт не открывает браузер и не запускает HTTP-сервер. Вход выполняется отдельно штатным `login`.

Что попадает в архив:
- курсы, на которые вы записаны в СДО (список берётся из СДО, а не задан заранее);
- файлы (`resource`), папки с подпапками (`folder`), страницы (`page`) в виде Markdown (только текст и ссылки), описание задания и приложенные к нему файлы (`assign`), текстовые блоки (`label`);
- внешние ссылки (`url`) только записываются, по ним ничего не скачивается;
- ресурсы ЭБС «Лань» (`lanebs`) сохраняются как отдельные HTML-карточки: название, библиографическая запись и страница (если указаны в СДО), ссылка на книгу и исходный ресурс СДО. Полные тексты, внешние обложки и модуль чтения не запрашиваются. В манифесте это `status=metadata_only`, `fulltext_downloaded=false`, в итогах — счётчик `metadata_only`. Ссылки с главной страницы курса ведут на локальные карточки; `complete` не означает наличие полных текстов внешней библиотеки;
- `manifest.json` и `README.md` по каждому курсу: что сохранено, пропущено, не поддерживается или не скачалось, с адресами (без `sesskey`/токенов), размерами и ошибками.
- `course.html` — статический снимок главной страницы курса: разделы, описания, объявления и ссылки на сохранённые материалы. Страницы материалов (`page`, `folder`, HTML-обёртки `resource`, описание `assign`) также сохраняются в HTML. Доступные изображения преподавателя с СДО встраиваются в снимки, а ссылки на выгруженные файлы и страницы заменяются локальными.

Это снимок доступного серверного HTML, не интерактивный клон Moodle и не точная копия оформления: оригинальные скрипты, стили, формы, личные статусы сдачи и сессионные данные исключаются. Содержимое, подгружаемое только JavaScript, не гарантируется. Внешние изображения, SVG, видео и неподдерживаемые ресурсы не скачиваются автоматически; причины пропусков изображений указаны в `page_snapshot.omissions`, такая выгрузка отмечается неполной. CLI и MCP для снимков те же — отдельной команды или сервера нет.

Что не открывается вообще: тесты, попытки, посещаемость, форумы и другие интерактивные элементы, ваши отправленные файлы и отзывы преподавателя. Загрузчик материалов выполняет только `GET` на `https://online-edu.mirea.ru` по белому списку путей и проверяет каждый редирект; вход и предварительное получение списка курсов используют отдельный клиент СДО со штатным SSO. Если загрузчик получил страницу входа, экспорт останавливается со статусом `relogin_required`. Сохранённая сессия не удаляется: сначала `verify-login`, новый вход нужен только если повторная проверка не помогла.

ZIP записывается постепенно на диск: **общего потолка размера курса или всех материалов по умолчанию нет**. Один ответ всё ещё буферизуется в памяти: файл до 50 МиБ, HTML до 5 МиБ; до 300 элементов в курсе и 200 файлов в папке. Скачивание последовательное. При использовании Python API можно явно задать `ExportLimits(max_total_bytes=..., max_course_bytes=...)`: это жёсткий лимит **несжатых материалов**, не физического ZIP. Служебные README и манифест имеют отдельный суммарный резерв 16 МиБ; учёт приведён в `byte_budget`. Внешний Python API без `output` сохраняет совместимость с небольшими ZIP в памяти; CLI/MCP всегда используют диск.

Если что-то не влезло, не скачалось или штатно отменено, результат содержит `partial`/`cancelled`/`relogin_required` и причины в манифесте. При аварийном прерывании или нехватке диска уже созданный уникальный архив сохраняется, но может быть незавершённым; успешный результат не обещается. Автоматической очистки и проверки свободного места заранее нет. Курс без распознанных элементов и пустой список курсов — ошибка. Разбор зависит от разметки Moodle. Картинки PNG/JPEG/GIF/WebP из разрешённых областей преподавателя встраиваются в HTML в пределах лимитов; внешние изображения не скачиваются.

## Инструменты

| Инструмент | Нужен вход | Что делает |
|---|:---:|---|
| `timetable` | — | Расписание группы, преподавателя или аудитории на N дней |
| `search_timetable` | — | Поиск группы, преподавателя или аудитории |
| `free_rooms` | — | Свободные аудитории в интервал: список по корпусу или проверка конкретных |
| `my_schedule` | ✓ | Своё расписание из Пульса |
| `my_grades` | ✓ | Баллы БРС по всем предметам |
| `my_attendance` | ✓ | Посещаемость по дисциплине |
| `my_turnstile_events` | ✓ | Проходы через турникеты за сегодня |
| `my_sdo` | ✓ | СДО (Moodle): курсы, дедлайны, оценки |
| `export_materials` | ✓ | Материалы всех курсов или одного курса в локальный ZIP (только stdio) |
| `whoami` | — | Есть ли сохранённая сессия; это не проверка доступа сервера |
| `verify_login` | кандидат | Проверка сохранённого кандидата без пароля/кода, новые зашифрованные версии (только stdio) |
| `login` | — | Открыть страницу входа МИРЭА на этом компьютере (только локальный режим) |
| `delete_my_data` | — | В локальном режиме запрещён и ничего не удаляет; удалённый режим не менялся |

Данные МИРЭА только читаются. `export_materials` создаёт локальные файлы; `verify_login` — новые зашифрованные версии сессии. Локальные истёкшие сессии не удаляются. Отметки посещаемости здесь нет.

## Подключение к удалённому серверу

Нужен адрес сервера вида `https://<хост>/mcp`. На главной странице сервера есть подсказки по клиентам.

- **claude.ai / Claude Desktop:** Настройки → Коннекторы → «Добавить свой коннектор» → вставьте адрес.
- **Claude Code:**
  ```bash
  claude mcp add --transport http mirea https://<хост>/mcp
  ```
- **Cursor и другие:** добавьте HTTP MCP-сервер с этим адресом.

При подключении откроется страница входа МИРЭА. Когда сессия Пульса истечёт (МИРЭА периодически сбрасывает их), ассистент попросит переподключить коннектор. Это делается в настройках клиента, в чат ничего вводить не нужно.

## Свой сервер

> Legacy self-host-режим сохранён для совместимости. В релизе 0.2.0 живые проверки относятся к локальному CLI/stdio, не к публичному OAuth-развёртыванию. Перед размещением чужих учётных данных требуется отдельная проверка серверной авторизации, изоляции и эксплуатации.

Удалённый сервер нужен, чтобы коннектор работал в веб-версии claude.ai и на телефоне. Он подключается по ссылке через OAuth: при подключении открывается страница входа МИРЭА, а без аккаунта доступен гостевой режим с публичным расписанием. В этом режиме сессии студентов хранятся на сервере того, кто его поднял, поэтому поднимайте его для себя и тех, кто вам доверяет.

**Ресурсы.** Подтверждённого нагрузочного профиля для многопользовательского сервера нет. Доступ к МИРЭА зависит от сети и политики университета; наличие работающего локального входа не доказывает доступность с VPS.

### Docker

```bash
git clone https://github.com/atomic-pancake-49/mirea-connect
cd mirea-connect
cp .env.example .env      # впишите PUBLIC_URL
docker compose up -d --build
```

Сервер слушает `127.0.0.1:8000`, данные лежат в `./data`: база SQLite и ключ шифрования `data/key`. **Сохраните ключ**: без него сессии не расшифровать.

### Без Docker

```bash
uv tool install https://github.com/atomic-pancake-49/mirea-connect/archive/refs/heads/main.zip
PUBLIC_URL=https://mirea.example.com DATA_DIR=~/.local/share/mirea-connect mirea-connect serve
```

### Наружу без белого IP

Клиентам нужен HTTPS-адрес. Подойдёт любой из вариантов:

**Cloudflare Tunnel** (нужен домен в Cloudflare, бесплатно):
1. Cloudflare Zero Trust → Networks → Tunnels → Create tunnel → скопируйте токен в `CLOUDFLARE_TUNNEL_TOKEN` в `.env`.
2. В настройках туннеля добавьте Public hostname, например `mirea.example.com` → `http://mirea-connect:8000`.
3. В `.env` укажите `PUBLIC_URL=https://mirea.example.com` и запустите:
   ```bash
   docker compose --profile tunnel up -d --build
   ```

**Tailscale Funnel** (домен не нужен, адрес вида `https://<машина>.<tailnet>.ts.net`):
```bash
tailscale funnel --bg 8000
```
В `PUBLIC_URL` впишите адрес, который покажет команда.

На VPS доступ к Pulse может отличаться от домашней сети; наличие `MIREA_PROXY` само по себе не доказывает работоспособность.

### Настройки (`.env`)

| Переменная | По умолчанию | |
|---|---|---|
| `PUBLIC_URL` | `http://localhost:8000` | Внешний адрес. Должен совпадать с тем, что вводят в клиенте |
| `SESSION_KEYS` | генерируется в `data/key` | Ключ шифрования сессий. Через запятую можно передать несколько для ротации: первый шифрует, остальные только расшифровывают |
| `ALLOW_GUEST` | `true` | Разрешить вход без аккаунта МИРЭА |
| `MIREA_PROXY` | — | HTTP/SOCKS-прокси для запросов к МИРЭА |
| `ALLOWED_HOSTS` | — | Дополнительные значения заголовка Host через запятую |
| `HOST` / `PORT` | `127.0.0.1` / `8000` | Где слушать (в Docker `0.0.0.0`) |
| `DATA_DIR` | `./data` | Каталог для базы и ключа |

## Безопасность

- **Пароль МИРЭА** проходит через сервер один раз при входе и не записывается ни в базу, ни в логи.
- **Сессия Пульса** хранится зашифрованной (Fernet + HKDF из pymirea) и привязана к пользователю. Токены коннектора и OAuth-коды хранятся только в виде хешей SHA-256.
- **Изоляция пользователей.** Каждый видит только свои данные. Владелец сервера технически может получить доступ к сессиям на своём сервере, поэтому есть self-host.
- **Удаление данных.** В локальном CLI/stdio автоматическое и явное удаление отключены: старые и истёкшие версии остаются. Описанное серверное удаление/отзыв токенов относится только к удалённому режиму и этим локальным ремонтом не менялось.
- **Ограничение попыток входа:** 10 попыток за 10 минут с одного IP и 5 на одну попытку подключения.

## Разработка

```bash
pip install -e ".[dev]"
pytest -q
ruff check .
```

Тесты проходят весь путь удалённого режима: регистрация клиента → `/authorize` → страница входа (гость, логин + OTP) → обмен кода → вызовы инструментов по MCP. Для локального режима проверяются страница входа на `127.0.0.1` и установщик. Экспорт материалов (`tests/test_materials.py`) проверяется на синтетическом HTML Moodle и сессии в памяти, то есть это не проверка на живом СДО. Запросы к МИРЭА в тестах мокаются.

## Источники

- **[atomic-pancake-49/pymirea](https://github.com/atomic-pancake-49/pymirea)**, форк [daftrent/pymirea](https://github.com/daftrent/pymirea) (MIT). Вся работа с МИРЭА: вход через SSO с 2FA, клиенты Пульса, БРС, СКУД, расписание, шифрование сессий.
- **[PowerTronin/mirea-mcp](https://github.com/PowerTronin/mirea-mcp)** (GPL-3.0). Оттуда взяты принципы: пароль не идёт через чат, инструменты только читают. Код не копировался. Это MCP для СДО (online-edu.mirea.ru) с курсами и дедлайнами, и он хорошо дополняет этот коннектор.
- **[mirea.ninja](https://mirea.ninja)** ([0niel/university-app](https://github.com/0niel/university-app)) — публичное расписание и свободные аудитории через их Supabase (`supabase.mirea.ninja`, публичные RPC с publishable-ключом). Запасной источник — официальный iCal `schedule-of.mirea.ru`. Старый `app-api.mirea.ninja` не используется.

Проект неофициальный и с РТУ МИРЭА не связан. Пульс — закрытый API, поэтому после изменений на стороне университета что-то может сломаться.
