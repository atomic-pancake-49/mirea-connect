# Установка MIREA Connect: инструкция для ИИ-агента

Эту инструкцию читает ИИ-агент (харнесс), которого пользователь попросил подключить MIREA Connect. Выполни шаги по порядку, на каждом спрашивая подтверждение пользователя перед изменением файлов.

## Что это

MIREA Connect — локальный MCP-сервер (транспорт **stdio**) для РТУ МИРЭА: расписание, баллы БРС, посещаемость, турникеты, СДО (курсы/дедлайны/оценки в Moodle), экспорт материалов в ZIP, публичное расписание. Каждый пользователь входит со своей учёткой на своём компьютере; экспорт сохраняется в `~/mirea-connect-exports/` или абсолютный `MIREA_EXPORT_DIR`. Университетские данные только читаются; скачивание создаёт локальные файлы.

## 1. Установить

Если команда `mirea-connect` уже есть (`mirea-connect --version`), пропусти этот шаг.

macOS / Linux:
```bash
curl -LsSf https://raw.githubusercontent.com/atomic-pancake-49/mirea-connect/main/install.sh | sh
```

Windows (PowerShell):
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/atomic-pancake-49/mirea-connect/main/install.ps1 | iex"
```

Скрипт сам подключит коннектор к Claude Desktop, Claude Code, Cursor, Codex, Hermes Agent и OpenClaw, если найдёт их. Если ты — один из них, перезапусти MCP-серверы и переходи к шагу 3.

## 2. Подключить к своему харнессу

Получи точную команду запуска для этого компьютера:

```bash
mirea-connect prompt --json
```

Ответ: `{"name": "mirea", "command": "<абсолютный путь к python>", "args": ["-m", "mirea_connect", "local"], "transport": "stdio"}`.

Добавь в конфигурацию MCP своего харнесса stdio-сервер с этими `command` и `args`, без переменных окружения и без рабочего каталога. Используй абсолютный путь из `command`, а не `mirea-connect`: у GUI-приложений часто другой `PATH`. Если у харнесса есть своя команда добавления MCP-сервера (вида `<harness> mcp add …`), используй её, иначе отредактируй его конфиг. Перед правкой файла сохрани копию. Затем перезапусти или перезагрузи MCP-серверы.

Типичные форматы для справки:
- JSON с `mcpServers`: `{"mcpServers": {"mirea": {"command": "...", "args": ["-m", "mirea_connect", "local"]}}}`
- TOML: `[mcp_servers.mirea]`, затем `command = "..."` и `args = ["-m", "mirea_connect", "local"]`
- YAML: `mcp_servers:` → `mirea:` → `command: ...`, `args: [...]`

## 3. Проверить и войти

1. Убедись, что появились инструменты `timetable`, `my_grades`, `verify_login`, `export_materials`, `login`. Вызови `whoami`: это наличие сохранённой сессии, не живая проверка университета. В Hermes Desktop команда `/reload-mcp` может отсутствовать: используй доступное управление подключениями или предложи перезапуск клиента; не выдумывай slash-команду.
2. Сначала `verify_login`, если есть сохранённый кандидат. Только если его нет или проверка не помогла, вызови `login`: он вернёт ссылку на `http://127.0.0.1:…` и откроет браузер. Дай ссылку пользователю. **Никогда не спрашивай пароль или код МИРЭА в чате**: пользователь вводит их только на этой странице. Официальный необязательный шаг настройки MAX пропускается только если SSO сам предлагает пропуск; обязательный MFA не обходится.
3. Если браузер недоступен, например на сервере по SSH, попроси пользователя выполнить в терминале `mirea-connect login`.
4. Проверка без входа: `timetable` с `kind="group"` и названием группы, например `ЭФБО-01-24`.

## Отключение

```bash
mirea-connect uninstall
```

Отключение меняет только подключение клиента. `mirea-connect logout` не удаляет сессию: зашифрованные версии сохраняются; автоматической очистки нет. Не удаляй ключи/сессии и не запускай удаление пакетов без отдельного решения пользователя. Перед изменением конфигурации сохрани отдельную копию.
